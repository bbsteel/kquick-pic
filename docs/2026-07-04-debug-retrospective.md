# 2026-07-04 修复复盘:SteamOS Wayland 迁移引发的连环故障

## 一、背景:一次系统升级,五层地基同时更换

2026-07-03 下午,SteamOS 3.8.13(build 20260701)把桌面模式从 **X11 会话**整体切换为 **Plasma 6.4 Wayland 会话**(journal 实证:升级前的 boot 只有 `kwin_x11`,升级后只有 `kwin_wayland`)。对一个"托盘常驻 + 全局热键 + 全屏选区截图"的工具来说,它依赖的每一层都变了:

| 依赖 | X11 时代 | Wayland 时代 | 后果 |
|---|---|---|---|
| 截屏 | mss / XGetImage 直读 | 合成器持有帧,X11 API 读不到 | 必须走 Portal 或 KWin 接口 |
| 全局热键 | XRecord 旁路监听 | 按键由合成器分发,XWayland 只见 X11 应用的键 | pynput 半残 |
| 窗口管理 | KWin X11 | KWin Wayland + XWayland 桥接 | 焦点/动画/反馈行为全变 |
| 输入法 | XIM/fcitx 直连 | 焦点语义变化,IM 激活依赖真焦点 | 弱依赖变强依赖 |
| 托盘 | SNI over D-Bus | 不变 | (唯一没变的) |

## 三、为什么修了这么多轮?

**这不是一个 bug,是一次误诊引发的债务链。**

最初的现象只有一个:"截屏时鼠标处图标弹跳"。7-03 的修复(`2d2d9d4`)把它归因于"KWin 对 MapNotify 的窗口打开动画",于是发明了"窗口常驻 mapped + opacity 切换"的规避方案。这个归因是**错的**——弹跳是 Portal 拉起进程的启动反馈,跟窗口 map 没有任何关系。但错误归因不会立刻暴露:

1. 常驻方案"看起来缓解了"(实际是观察噪声),误诊被当成了结论;
2. 常驻 hack 本身埋下黑屏炸弹(跨熄屏周期的合成器状态异常);
3. 我沿着同一错误病因再进一步(POPUP 免管理窗口),弹跳依旧(当然依旧,病因就不在窗口),还赔进去文字输入(POPUP 拿不到焦点);
4. 直到做了隔离实验,把"Portal 调用 / 窗口 map / 键鼠抓取"三个动作拆开单独执行,弹跳才当场定罪给 Portal——之前两轮"修复"瞬间全部失去存在理由。

**每一轮返工的成本,本质上都是在偿还第一轮"没有验证归因"欠下的债。** 类似地,"高亮丢失"表面上像截屏问题,实际是热键机制问题(按键透传),两者在现象层完全纠缠——KWin 直采上线后弹跳消失、高亮依旧,才把两个问题切割开。

## 四、为什么这么难修?

1. **现象与根因隔了 2~4 层系统。** "弹跳图标"的因果链是:app 调 Portal → xdg-desktop-portal-kde 拉起辅助进程 → Plasma 启动反馈 → 光标旁画图标。代码里没有任何一行"画了弹跳",日志里没有任何报错。这类问题 grep 不到、栈追不到,只能靠受控实验二分。

2. **多个独立故障共享同一现象层。** 弹跳(Portal)、高亮丢失(按键透传)、黑屏(常驻窗口)、退不掉(menu id + 双实例)——四个互不相干的根因,症状全部表现为"截图工具行为怪异"。任何"一个补丁解释一切"的尝试注定失败,但人和模型都天然倾向找统一解释。

3. **反馈回路又慢又浑浊。** 每个假设要重启应用、真人按键、肉眼看光标,一轮几分钟;观察本身还有噪声(双实例期间,两个进程同时响应热键,任何实验结论都被污染)。

4. **知识盲区叠加。** KWin 6.4 的 ScreenShot2 授权机制(按 `/proc/pid/exe` 匹配 desktop 文件 Exec 规范路径)、KGlobalAccel 的 D-Bus 协议、XWayland 对 override-redirect 窗口的焦点语义、dbusmenu 的 id 契约——这些组合在公开语料里几乎不存在成体系的记载,先验知识必然不足,**任何人/任何模型第一次的猜测大概率是错的**。

## 五、关于模型在这类任务上的准确率

这类任务的困难对所有 LLM 是同构的,值得诚实地讨论:

**1. 单步准确率 ≠ 长链条成功率。** 假设模型每一步判断有 90% 准确率,一条需要 8 步串行推理-验证的诊断链,端到端成功率只有 ~43%。错误还会复利:一次错误归因(如"弹跳=窗口动画")会让后续所有努力在错误的搜索子空间里精耕细作——投入越多,离真相越远。今天大部分轮次消耗在这里。

**2. 诊断任务的瓶颈不是"想",是"测"。** 写代码时,模型的先验知识直接命中答案;诊断时,答案不在上下文里也不在权重里,必须**主动设计实验制造新信息**。今天每一个突破口都来自实验而非推理:
- T1/T2/T3 三段隔离测试 → 弹跳定罪 Portal(推翻了两轮"合理"的修复);
- 8 秒倒计时无按键纯截帧 → 高亮丢失定罪按键透传(截图代码完全无辜);
- `dbus-send` 手工重放 Plasma 的菜单点击 → 退出失效定罪 id 错位(3 分钟锁死,零猜测);
- 直接 introspect KWin/KGlobalAccel 的 live D-Bus 接口拿真实签名,而不是凭记忆写调用。

**3. 模型间的差异主要体现在"纪律"而非"知识"。** 面对反证时是修正假设还是再打一层补丁;是先验证归因再动手,还是先动手再解释;是把"看起来好了"当结论,还是坚持复现-消除-复测。较弱的模型并非不知道这些原则,而是在长上下文、多轮挫败、用户催促的压力下更容易放弃它们,退化成"试一下这个呢"的随机游走。之前的轮次里,"常驻窗口"、"POPUP"、"XSetInputFocus"每一步孤立看都合理,连起来就是在未经验证的病因上叠 workaround。

**4. 我这次成功,有方法论的因素,也有便宜可占。** 必须说清楚:
- 我接手时,前几轮已经**消除了大量错误分支**(排除了托盘实现、排除了 mss、暴露了常驻 hack 的副作用),失败也是信息;
- 用户全程在场,能按键、能盯光标、能回答"哪个阶段弹了"——隔离实验的价值全靠这个人肉观测端点;
- 我自己也犯错:POPUP 方案赔掉文字输入、XSetInputFocus 猜错一次、第一次杀旧实例被沙箱 /proc 误导。区别不在零失误,而在**每次失误后用实验收敛,而不是用新猜测发散**。

一句话总结:**在"现象离根因很远"的系统级调试里,模型的价值不取决于它知道多少,而取决于它能否把自己不知道的东西,变成一个可执行、可观测、能一锤定音的实验。**

## 六、"知识"从哪来:这次到底读了什么

复盘时口头说过"读 KWin 源码搞懂授权机制"——这个说法必须修正:**当时尝试在线抓取 KWin 源码(invent.kde.org 的 screenshotdbusinterface2.cpp),返回 502,实际没有读到。** 真实的信息来源分三层,可靠性递增:

| 层 | 内容 | 性质 |
|---|---|---|
| 训练记忆 | ScreenShot2 授权机制(`/proc/pid/exe` 规范路径 ↔ desktop 文件 Exec 首参数匹配,读 `X-KDE-DBUS-Restricted-Interfaces`,对应 kwin 源码 `screenshotdbusinterface2.cpp` + `utils/serviceutils.h`);KGlobalAccel 的 flag 值(SetPresent=2、NoAutoloading=4) | **只配当假设**——可能记错、可能版本漂移 |
| live introspection | `dbus-send ... Introspect` 打在运行中的服务上:ScreenShot2 的 7 个 Capture 方法、`/kglobalaccel` 的 `setShortcut(as,ai,u)` / `setForeignShortcut` 精确签名、`/component/*` 的 `globalShortcutPressed(s,s,x)` 信号;以及 `kglobalshortcutsrc`(Alt+F1 占用方)、journal(kwin_x11→kwin_wayland 分界) | **证据**——运行中二进制自己吐出的事实,但只有类型签名,没有语义和枚举值 |
| 探针实验 | desktop 授权改完 → `kbuildsycoca6` → 探针脚本一次拿到 3840x2160 原始帧;KGlobalAccel 注册后用户实按 Alt+F1 触发回调 | **判决**——假设错了会当场失败,通过了记忆才升格为结论 |

如果那个授权探针失败了,才会真正需要把源码抓下来读(换 GitHub 镜像)。POPUP 焦点问题则完全没有源码参与:GTK/X11 焦点语义的先验知识 + 用户实测"打不了字"反推,XSetInputFocus 那次猜测也确实错了。

这引出一个值得记录的观点(源自用户的观察):**"Linux 显示栈这类冷僻知识对模型难度高"——对,但只对了一半。**

- 对的部分:X11/Wayland/KWin/XWayland/fcitx 的组合案例在公开语料里确实稀少,且版本敏感(KWin 6.4 是 2024 之后的东西),模型先验准确率必然低。
- 需要修正的第一点:冷僻知识的真正杀伤不在"不知道",而在**错误的先验感觉起来很合理,又没有编译器/测试当场打脸**。主流领域(Web/CRUD)里知识错了会立刻编译失败或测试爆红;这个领域里知识错了只会变成一次自信的误诊("弹跳=窗口动画"),然后消耗掉后面几轮。
- 需要修正的第二点:比单点知识更冷的是**跨层组合**。每一层的文档其实都存在,但"Portal 每次调用拉起辅助进程→触发启动反馈"、"XRecord 被动监听→按键透传→终端清选区→截帧无高亮"这类因果链在任何文档、任何语料里都没有成文记载——它们只存在于这台机器的运行时里。再大的训练集也覆盖不了组合爆炸,所以出路不是"知道更多",而是把每个疑问变成一个可执行的实验。
- 推论:冷僻度对所有模型一样冷,它真正改变的是**验证成本**——记忆不可信 → 每一步都要 introspect/探针 → 诊断链变长 → 单步错误率的复利更凶。在这种领域里,模型间拉开差距的是"是否坚持为每个假设付验证成本",而不是谁的语料里恰好多几篇 KWin 文章。

## 七、遗留事项与风险

- **Alt+F1 夺回机制**:Plasma 重新登录后启动器挂件可能重新抢占该键,应用每次启动会自动解绑夺回(有日志 `unbinding it`)。若某天热键失灵,先查这条日志。
- **ScreenShot2 授权是隐性依赖**:`~/.local/share/applications/kuick-pic.desktop` 的 `Exec` 必须保持 `.venv/bin/python3 -m kuick_pic` 且含 `X-KDE-DBUS-Restricted-Interfaces=org.kde.KWin.ScreenShot2`。授权失效不会报错,只会静默回退 Portal——**弹跳图标复现就是报警信号**。`install.sh` 已固化此配置。
- **仓库根目录与 scripts/ 下各有一个未提交的 `start.sh`**(功能重复,一中文一英文),去留待定。
- **Route B(Tauri 重构)**:今日修复后 GTK 方案在 Wayland 下已完整可用,重构的紧迫性下降,可重新评估优先级。
